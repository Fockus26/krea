# D103 · Components · NumberStepper con `value: number | null` y `aria-labelledby`; supera la parte "0 + Sin puntuar" de D055 · Implemented

**Decision:** `NumberStepper` acepta `value: number | null` (`onChange` sigue recibiendo siempre un número). `null` = sin valor: el campo se ve vacío (nunca "0", D003), el `spinbutton` no lleva `aria-valuenow` y su `aria-valuetext` es `emptyText` ("Sin puntuar" por defecto); − y + no se deshabilitan y el primer −/+ (o ↑/↓) fija `min` en las dos direcciones; vaciar el campo o escribir algo inválido vuelve al valor anterior, también a `null`. Prop nueva `aria-labelledby` como alternativa a `label`: nombra el `fieldset` y el campo, y si viene `label` no se usa. Lógica pura en `lib/stepper.ts` (`stepFrom`, `stepperDisplay`, `stepperAria`, `STEPPER_EMPTY_TEXT`; `atMin`/`atMax` aceptan `null`). `ScorePicker` (> 6) quita el rodeo de D055: ya no pasa `value ?? 0` ni pinta "Sin puntuar" con `aria-describedby`, y su `fieldset` externo pasa a ser un `div` que solo recoge las teclas 0–9 y `,`; el stepper se nombra con el enunciado (`aria-labelledby={labelledBy}`), como el radiogroup de ≤ 6. La API pública de `ScorePicker` no cambia. D055 queda vigente en atajos y nombres accesibles; su última frase ("stepper sin puntuar = 0 + Sin puntuar") la supera esta decisión.
**Why:** una pregunta sin puntuar no vale 0 (D003) y el "0" mudo del campo invitaba a leerla así; el nombre "Puntaje" del campo era provisional (checklist 44) y el enunciado lo nombra mejor. Partir de `min` en las dos direcciones hace que el primer toque fije un valor visible y nunca uno lejano. El tipo numérico de siempre sigue compilando igual (Alumnos, base 10–20).
**Discarded alternative:** que el primer + dé `min + paso` — en un puntaje 0–8 nunca se podría fijar 0 con un solo toque. Un `placeholder` "—" en el campo vacío — contraste de placeholder bajo y el lector ya dice "Sin puntuar".
