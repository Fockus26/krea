# D418 · Components · El formulario del capitán es el de siempre, precargado con lo aceptado; lo aceptado gana al borrador · Implemented

**Decision:** el capitán sigue respondiendo con `TaskAnswerForm`: la página le pasa `inicial` con las partes **aceptadas** (`aceptadas` → `inicialEdicion`, imágenes firmadas), `prioridad` con esas preguntas y `key` = el mayor `actualizadoEn` de lo aceptado. Aceptar, devolver y reasignar son Server Actions con `refresh()`: el servidor es la fuente y, si cambió lo aceptado, el formulario se remonta con lo nuevo. Al restaurar el borrador del teléfono, las preguntas de `prioridad` se saltan (antes el borrador ganaba siempre sobre `inicial`). El capitán puede editar cualquier respuesta antes de enviar; lo que se envía son las respuestas del formulario (D012) y el crédito de participación sale de las partes, no de quién tecleó.
**Why:** cero formulario nuevo para el capitán y la cola sin conexión (D292) sigue igual; si el borrador ganara, una parte recién aceptada no aparecería en un teléfono que ya tenía algo escrito.
**Discarded alternative:** copiar la parte aceptada al borrador desde el cliente — dos fuentes de verdad y se pierde si el capitán cambia de teléfono; que el servidor arme la entrega con las partes — el capitán no podría corregirlas antes de enviar.
