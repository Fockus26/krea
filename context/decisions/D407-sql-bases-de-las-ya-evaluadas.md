# D407 · Data · Las entregas ya evaluadas conservan su base: SQL de datos que les pone la vigente · Pending

**Decision:** `scripts/sql/2026-11-14-bases-por-entrega.sql` (SQL de datos, no migración; lo aplica César en `krea_preview` y en `krea`): a cada entrega `evaluada` cuya evaluación no trae `bases` le pone la base vigente de cada integrante que existe (`jsonb_object_agg` sobre `unnest(integrantes)` ⨝ `usuarios`), y lo mismo a `evaluacion_anterior.previa` cuando existe y no la trae. No toca las que ya traen `bases` ni las sin evaluar; la nota y el ranking no cambian (es la misma base). Idempotente y con una consulta de comprobación al final. Probado sobre PGlite (`tests/db/base-por-tarea.test.ts`). Hasta que se aplique, una evaluación sin `bases` sigue la base vigente (el respaldo de D403): un cambio de base en «Editar alumno» antes de aplicarlo movería esas notas como hasta ahora. Pasa a Implemented cuando César lo aplique en `krea`.
**Why:** César decidió que «las entregas ya evaluadas conservan la suya»; sin congelarlas, el primer cambio de base después del despliegue movería todas las tareas viejas de ese alumno.
**Discarded alternative:** dejar el respaldo para siempre (las viejas seguirían cambiando con la base de «Editar alumno», justo lo que el pedido quiere evitar); una migración de drizzle que lo haga (los datos no son esquema y el kit separa las migraciones de los SQL de datos, como D388).
