# D192 · Auth · «Cambiar contraseña» en Perfil: verifica la actual con Identity Toolkit, cambia con el Admin SDK, revoca y reabre solo esta sesión · Implemented

**Decision:** Server Action `cambiarPassword` (`lib/acciones/perfil.ts`): `zCambioPassword` (actual no vacía, nueva ≥ `PASSWORD_MIN`), comprueba la actual con `accounts:signInWithPassword` (REST, `lib/firebase/password.ts`; el emulador si `FIREBASE_AUTH_EMULATOR_HOST`), `updateUser` + `revokeRefreshTokens` (cierra todas las sesiones) y vuelve a entrar con la nueva para crear una cookie nueva solo para este navegador. Si no se puede reabrir, borra la cookie y la página manda a Ingresar. Errores: «actual» en su campo (con foco), bloqueo/red en una alerta del diálogo.
**Why:** el Admin SDK no comprueba contraseñas; la revocación es lo que cierra las otras sesiones (lo pide el lienzo con «Cerramos tus otras sesiones»).
**Discarded alternative:** `reauthenticateWithCredential` + `updatePassword` en el navegador — deja el cambio fuera del servidor (D175) y no revoca las cookies de otros equipos. Ojo: si la API key pública tiene restricción por referer HTTP, la llamada REST del servidor falla (ver informe de W4).
