# D266 · Sections · «Crear premio» en Premios y «Editar / Agregar premio» en la tarjeta: un diálogo y una Server Action `guardarPremio` · Implemented

**Decision:** botón «Crear premio» en las acciones del `PageHeader` de Premios → `PrizeDialog`: elegir una tarea sin premio (grupal o individual, ni cerrada ni importada; `tareasParaPremio`), el texto (obligatorio, ≤ 200) y una foto opcional (D265). Cada tarjeta de una tarea editable lleva «Editar premio» (con premio) o «Agregar premio» (por definir), que abren el mismo diálogo con la tarea fija; la foto se mantiene, se cambia o se quita. `guardarPremio(FormData)` (`exigirSesion("profesor")`, zod, foto validada, `refresh()`) sube la foto y escribe `premio` + `premioFoto` en una transacción (`armarPremio`: solo tareas no cerradas; el documento tiene que seguir validando); es un `update`, así que el doble envío no duplica (y el botón queda deshabilitado mientras vuela). El tablero adopta las tarjetas nuevas cuando llegan por props tras el `refresh()`. Quitar el premio sigue en el constructor. La galería (`/secciones/premios`) sigue con el enlace al constructor. Copy provisional (fila 147).
**Why:** pedido 7 de César («poder crear premios»); editar desde la tarjeta cabe sin rediseñarla (un botón secundario como el «Agregar premio» que ya había).
**Discarded alternative:** «Crear premio» que lleve al constructor — obliga a buscar la tarea y no sube fotos; quitar el premio desde el diálogo — necesita confirmación propia y ya existe en el constructor.
