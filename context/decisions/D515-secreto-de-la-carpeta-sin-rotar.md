# D515 · Datos · La carpeta queda atada a `BETTER_AUTH_SECRET`: rotar el secreto exige volver a migrar; el script se niega con otro secreto · Implemented

**Decisión:** la carpeta depende del secreto del entorno que usa cada base (Preview → `krea_preview`, Production → `krea`; iguales o no, cada base se migra con el de su app). El script usa el secreto que le pasan (`--entorno` con el archivo de `vercel env pull`, o la variable) y comprueba que encaja: rutas ya en la carpeta nueva → coincide; rutas en carpetas desconocidas → no aplica sin `--aceptar-ajenas`. Como las rutas guardadas mandan, rotar el secreto no rompe lo existente: solo las subidas nuevas irían a otra carpeta y el reenvío de una entrega con imágenes anteriores se rechazaría (`incompleta`) hasta migrar con `crearCarpetaEntrega(viejo)` como `carpetaVieja`. Igual que el id público (D493), no se rota sin plan.
**Why:** el secreto hace la carpeta irreversible; atarla a un secreto aparte (`CARPETAS_SECRET`) añadiría una variable más que configurar en Vercel sin ganar nada mientras el de sesión no se rote.
**Discarded alternative:** variable propia para la carpeta (otra acción manual en Vercel y en el VPS) · aceptar al validar cualquier carpeta de 32 hex de la tarea (un alumno podría referenciar la imagen de otra entrega).
