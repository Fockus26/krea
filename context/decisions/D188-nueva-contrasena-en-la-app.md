# D188 · Auth · Nueva contraseña en `/recuperar/nueva` con el `oobCode`: Identity Toolkit desde el servidor, revoca sesiones y vuelve a Ingresar con aviso · Implemented

**Decision:** el correo no lleva el enlace de Firebase sino el de la app: del enlace del Admin SDK se toma el `oobCode` y se arma `<sitio>/recuperar/nueva?mode=resetPassword&oobCode=…` (`enlaceRestablecer`; sin `actionCodeSettings`, así no hace falta autorizar dominios en la consola). La página comprueba el código en el servidor sin gastarlo (`accounts:resetPassword` solo con `oobCode`) y muestra el formulario o «Este enlace ya venció»; «Guardar contraseña» llama a la Server Action `restablecerPassword` (zod con `PASSWORD_MIN`), que gasta el código con `accounts:resetPassword` + `newPassword` (REST, `lib/firebase/password.ts`, coherente con D192), revoca todas las sesiones de la cuenta, borra la cookie de este navegador y la página manda a `/ingresar?aviso=password-nueva` («Listo: tu contraseña cambió…», leído en el navegador para que `/ingresar` siga estática). `/recuperar/nueva` es pública aunque haya sesión (el proxy no la redirige).
**Why:** el diseño tiene la pantalla propia (HANDOFF §3 y §5c: el enlace «apunta a `/recuperar/nueva`»); hacerlo en el servidor deja el cambio fuera del navegador (D175) y permite revocar.
**Discarded alternative:** `verifyPasswordResetCode` + `confirmPasswordReset` del SDK del navegador — no revoca las cookies de otros equipos. La página por defecto de Firebase — no es el diseño. Ojo: como en D192, si la API key pública tiene restricción por referer HTTP, la REST desde el servidor falla.
