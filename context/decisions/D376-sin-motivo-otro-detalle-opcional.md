# D376 · Data / UX · Ajustes de puntos: se quita «Otro»; el detalle es opcional siempre; los ajustes viejos se siguen mostrando · Implemented

**Decisión:** «Otro» deja de ser una opción (sale del catálogo inicial, de `chipMotivo` —ya no hay chip «± escribe»—, de `DETALLE_VACIO`, del error `"detalle"` y de la ayuda «Escribe el valor…»). El campo Detalle queda **opcional** para cualquier opción y su etiqueta dice «(opcional)». `zAplicarAjuste.motivoId` es un texto que no puede ser `anulacion` / `importado` / `otro`, y el ajuste solo se guarda si el id está en `config/motivos` (D375). Los ajustes guardados con `motivoId: "otro"` (o con el formato `Otro: "…"` del Panel, D101) se siguen leyendo y mostrando con su etiqueta guardada (`separarMotivo`, `motivoTexto`, `MOTIVO_OTRO` se conservan para eso). El filtro del Historial ofrece las opciones vigentes en su orden, luego las etiquetas del historial que ya no están (opciones borradas o renombradas, «Otro» viejo) por orden alfabético, y «Anulación» al final (`motivosFiltro`). Decisión de César, 2026-11-13.
**Why:** con opciones editables, «Otro» sobra: si falta un motivo, se crea. Sin «Otro» no hay un caso que obligue a escribir el detalle.
**Alternativas descartadas:** dejar «Otro» como opción no borrable (César pidió quitarlo) · el filtro solo con las vigentes (no dejaría filtrar los ajustes de opciones borradas).
