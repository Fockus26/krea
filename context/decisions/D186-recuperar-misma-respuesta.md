# D186 · Auth · Pedir el enlace responde igual y en el mismo tiempo exista o no la cuenta: el trabajo corre en `after` · Implemented

**Decision:** la Server Action `pedirEnlace` (`lib/acciones/recuperar.ts`) solo valida la cédula con zod y responde `{ ok: true }`; la búsqueda de `privados/{cedula}.email`, el límite, el enlace y el envío corren en `after()` (después de responder), así ni el contenido ni la duración de la respuesta dicen si la cédula tiene cuenta o email. «Revisa tu correo» ya no muestra el correo enmascarado: dice «Si esa cédula tiene un correo registrado, te enviamos un enlace» (`RecoverSent` sin `email`), y se muestra en `/recuperar` sin cambiar de ruta (la cédula queda en memoria para «Reenviar enlace»); `/recuperar/enviado` redirige a `/recuperar` (la pantalla con el correo de ejemplo sigue en `/secciones/ingresar/enviado`). Registros: solo códigos de resultado, nunca el email, el enlace ni el código.
**Why:** mostrar `y••••@gmail.com` para cualquier cédula tecleada revelaría qué cédulas tienen cuenta y parte de su correo (el pedido no exige sesión).
**Discarded alternative:** mostrar el correo enmascarado como en el lienzo — enumera cuentas. Esperar un tiempo fijo antes de responder — más lento para todos y frágil ante latencias de Brevo.
