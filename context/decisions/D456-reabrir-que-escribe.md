# D456 · Data · Reabrir: para todos cambia fecha y hora y borra prórrogas; para algunos reemplaza la lista entera de prórrogas · Implemented

**Decision:** `armarReabrir` (`lib/reabrir-tarea.ts`, puro). Para todos: `estado = abierta`, `fechaEntrega`/`horaEntrega` nuevas, `prorrogas = null` (también desde una cerrada a mano). Para algunos: el `estado` y la fecha general no cambian (sigue cerrada para los demás) y `prorrogas` pasa a ser **exactamente** los titulares enviados, todos con la misma fecha y hora nuevas; los que no van pierden la suya; la lista vacía las quita todas (cierra para todos). El servidor comprueba que cada titular sea un alumno (individual) o equipo (grupal) de las secciones de la tarea (`titularesValidos`, leídos en la transacción), que la tarea esté publicada, no importada y cerrada en `ahora`, y que la fecha cumpla `errorVencimientoNuevo` (desde hoy, ≤ 366 días, sin vencer). Si el pedido ya coincide con lo guardado devuelve ok sin escribir (idempotente). «Cerrar tarea» a mano borra las prórrogas (cierra para todos). Reabrir no cambia puntos (D007): sin recálculo del ranking. El aviso push no se manda al reabrir (`lib/push.ts` sin cambios: solo al publicar).
**Why:** una lista completa es lo que muestra el diálogo (marcados = con prórroga): es fácil de razonar, idempotente y sin estados intermedios.
**Discarded alternative:** una fecha por alumno — el diálogo crecería a un campo por fila para un caso que no se pidió; sumar prórrogas sin quitar — no habría forma de quitarlas desde el mismo diálogo, que el pedido exige.
