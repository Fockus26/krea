# D494 · Data · El ranking que recibe un alumno (página y sondeo) lleva ids públicos; el del profe sigue con cédulas · Implemented

**Decision:** `rankingPublico(r, idPublico)` cambia cada clave de `alumnos` por el id público y quita la `semilla` que aún contuviera la cédula (el avatar se dibuja con el id). Lo usan `/ranking` y `/ranking/equipos` (`inicial`) y `GET /api/ranking/<sección>` cuando la sesión es de alumno. `InfoEquipos.capitan` sale de `infoDeEquipos(…, idDe)` con el mismo mapa, y la fila «tú» se marca con `Tu = { id, equipoId }` (el id público propio, calculado en el servidor). El profe recibe las cédulas (`conCedula`): cada fila de su ranking enlaza a Alumnos. El cliente valida el sondeo con `zRankingPublico` (alumno) o `zRankingSeccion` (profe) según `rol`. Nada guardado cambia: `ranking.alumnos` en la base sigue con la cédula. QA v2 F-M1.
**Why:** el alumno recibía las 34 cédulas de su sección en el JSON y en el HTML de `/ranking`; la cédula es dato personal de menores y el usuario de ingreso.
**Discarded alternative:** guardar el ranking ya con ids públicos (el profe perdería el enlace a Alumnos y el servidor tendría que traducir para calcular puestos) · un solo formato para los dos roles (mismo motivo).
