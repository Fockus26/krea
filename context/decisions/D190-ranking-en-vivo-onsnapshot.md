# D190 · Data · Ranking en vivo: primera instantánea del servidor + `onSnapshot` en el navegador; chips y feed desde que se abre la página · Implemented

**Decision:** el servidor pinta `ranking/{seccion}` y `RankingEnVivo` (cliente) se suscribe con `onSnapshot` con el SDK del navegador (las reglas ya lo permitían, probado en `tests/rules/`). Si el navegador no tiene la sesión de Firebase de esa cuenta (otra pestaña cerró sesión, contraseña cambiada), pide un token personalizado para su propio uid (`tokenEnVivo`, Server Action con `verificarSesion`) y entra con `signInWithCustomToken`; un intento por montaje. Si falla o se corta: aviso `ErrorEnPantalla warn` y se queda lo último. El documento no guarda puestos anteriores: el chip de cada fila es lo que subió o bajó **desde que se abrió la página** (sin cambio, sin chip), el feed «Últimos movimientos» (≥ 1024) arranca vacío y se llena con la diferencia entre instantáneas, y bajo 1024 la región viva es `RankAnnouncer` (podio, subidas, caída a riesgo), nunca las dos (D096). Tema y capitán de cada equipo vienen del servidor (el ranking no los trae); logos de Storage, en W8.
**Why:** D011; no inventar deltas semanales sin historial; el SDK del navegador puede perder la sesión aunque la cookie siga valiendo.
**Discarded alternative:** guardar el puesto anterior en `ranking/{seccion}` — cambia el modelo y lo que escriben W6–W8; se puede añadir después. Leer el ranking solo en el servidor con refresco — no es en vivo.
