# D318 · Data · Renombrar o eliminar un año o una sección solo si está vacía; sin cascada · Implemented

**Decision:** cambiar el número de un año o la letra de una sección cambia su código («5A» → «4A»), y eliminarla lo borra: las dos cosas se permiten solo si la sección (o todas las del año) está vacía. Vacía = 0 usuarios con esa `seccion` (alumnos **y** profes asignados), 0 equipos, 0 tareas o borradores con ella en `secciones`, 0 entregas y 0 ajustes (`seccionVacia(uso)`). La pantalla lo calcula con los loaders ya cacheados (`usoPorSeccion`); la acción lo vuelve a comprobar dentro de la transacción sobre `config/secciones` con una consulta `limit(1)` por colección (`in` / `array-contains-any` con los códigos que se van, ≤ 26) y, si se va, borra `ranking/{codigo}`. Con datos, el botón sigue visible y el diálogo dice qué tiene y la regla (`bloqueoTexto`), no un `disabled` mudo. Crear lo que ya existe = error «Ya existe 5A» sin escribir; eliminar lo que ya no está = `ok` (doble clic).
**Why:** el código está copiado en usuarios, custom claims, equipos, tareas, entregas, ajustes, `ranking/{seccion}` y `decisionesPremio`. Reescribirlo todo en cascada no cabe en una transacción (límite de escrituras) y dejaría sesiones con el claim viejo; con la regla de vacío nada guardado cambia de nombre ni se pierde. Es lo que César decidió para eliminar, y renombrar tiene el mismo riesgo.
**Discarded alternative:** renombrar en cascada con datos (reescribir cada colección, regenerar claims y revocar sesiones): costoso, no atómico y arriesgado para un caso raro (un año se crea antes de tener alumnos). Si hace falta, se crea la sección nueva y se mueven los alumnos.
