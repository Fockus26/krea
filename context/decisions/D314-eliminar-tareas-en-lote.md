# D314 · Data · Eliminar tareas en lote: `eliminarTareas(ids)` reutiliza el borrado de una; `EliminarEnLote` por id · Implemented

**Decision:** en la vista Lista de Tareas, casillas (`useSeleccionLote`, Shift = rango, D310–D311) y la barra «N seleccionadas · Eliminar» (`EliminarEnLote`, D298–D300, ahora por `id` en vez de `cedula`: `ItemLote = { id, nombre }`, `ResultadoItem = { id, ok, … }`). La Server Action `eliminarTareas(ids)` (`lib/acciones/tareas.ts`) valida con `zIdsLote(zIdTareaProfe)` (sin repetir, 1..TOPE_LOTE; `zCedulasLote = zIdsLote(zCedula)`), exige sesión de profesor, borra una por una con `borrarUnaTarea` (el mismo cuerpo que `eliminarTarea`: transacción con el ranking, D242, y luego las imágenes de B2) y termina con un `refresh()`. Una tarea que ya no existe cuenta como borrada. El diálogo suma en el cliente la pérdida que ya trae cada tarea (`sumarPerdidas`; si alguna no la trae, el texto va sin cifras). `Sustantivo` gana `femenino` y `cosa` para concordar: «1 tarea seleccionada», «Ninguna tarea seleccionada», «¿Eliminar 3 tareas?» (sin la «a» de persona). Sin FLIP en el lote; si no quedan fallos, el foco va a la opción «Lista» del interruptor.
**Why:** pedido 56; el lote tenía que ser el mismo de Alumnos/Profesores, no uno nuevo.
**Discarded alternative:** una transacción para todas las tareas: con varias tareas grandes pasa el tope de 500 escrituras y un fallo tumbaría las demás.
