# D514 · Datos · Mientras se migra, el envío acepta también la carpeta vieja de la misma entrega; lo que queda sin uso se compara por archivo · Implemented

**Decisión:** `respuestasValidas` / `armarEntrega` / `esImagenDe` reciben `Carpetas` (una o varias); el envío y las partes pasan `carpetasDeEntrega(id)` = [nueva, vieja]. Las subidas nuevas van siempre a la nueva. La misma imagen (mismo `uuid`) en las dos carpetas cuenta repetida. `imagenesSinUso` y la parte que se reentrega comparan por archivo (`rutasSinUso`, `{uuid}.jpg`), no por ruta entera: si un formulario abierto antes de la migración manda la ruta vieja de una imagen ya movida, no se borra el objeto nuevo; la ruta vieja guardada la recoge la siguiente pasada del script (D513). Quitar la vieja de `carpetasDeEntrega` cuando el script haya corrido en `krea` y una segunda pasada no mueva nada (ítem para el backlog).
**Why:** entre el despliegue y el script, las entregas guardadas tienen rutas viejas y el reenvío o completar las manda tal cual: sin aceptarlas, el alumno no podría reenviar. Comparar la ruta entera, con un formulario viejo, borraba la imagen ya movida.
**Discarded alternative:** reescribir en el servidor la ruta vieja a la nueva (antes de correr el script la nueva no existe y la imagen se vería rota) · desplegar solo después de migrar (las subidas de ese intervalo irían a la carpeta vieja).
